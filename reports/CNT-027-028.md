## Mapa produktów (CNT-028)

| Stan | Liczba | Produkty |
| --- | --- | --- |
| Zmapowane | 62 z 64 | wszystkie poza poniższymi (wcześniej 7: ogórek, pomidor, ziemniaki, marchew, cebula, banan, jabłko) |
| Wyłączone | 2 | `salt` — sól: produkt spiżarniany o pomijalnej cenie; `water` — woda z kranu, oferty wody butelkowanej nie są składnikiem |

Zasady dopasowania (fail-closed):

- nazwa jest czyszczona: małe litery, bez diakrytyków (ł→l), interpunkcja → spacja, `%` zostaje;
- produkt trafia, gdy nazwa zawiera frazę z `any` jako osobne słowo (z odmianami, np.
  `pomidor|pomidory|pomidorki`, `jaja|jajka|jajko`), spełnia wszystkie wzorce `all`
  (np. makrela musi być „wędzona”, tuńczyk „w sosie własnym/w wodzie”, szynka „gotowana”)
  i nie zawiera żadnego wzorca `not` (np. tomato: `suszon`, `przecier`, `koncentrat`, `sos`…);
- fraza poprzedzona słowem zależnym (`z`, `ze`, `w`, `o`, `na`, `do`, `bez`, `smaku`…) nie
  liczy się („ser z czosnkiem”, „jogurt bez cukru”, „chleb z cebulą” to nie czosnek/cukier/cebula);
- globalne wyłączenia nazw pochodnych i nie-spożywczych: sok, nektar, napój, bulion, kostka
  rosołowa, „o smaku”, karma dla zwierząt, kosmetyki, sałatka, pizza, zupa, dżem, herbata itd.;
- gdy pasuje więcej niż jeden produkt („Pomidory i ogórki zestaw”), oferta jest pomijana.

Przykłady rozróżnień objęte testami: „sok pomidorowy” ≠ pomidor; „ser żółty” → `yellowcheese`,
„twaróg” → `cheese`; „masło orzechowe” ≠ masło; „mleko kokosowe” ≠ mleko; „pierś z kurczaka”
→ `chicken`, „bulion z kurczaka” — brak; „papryka słodka mielona” → `paprika`, „papryka
czerwona” → `pepper`; „ryż do sushi” → `sushirice`; „koper włoski” ≠ koperek.

Decyzja z powodu alergenów: `pasta` w katalogu to „makaron pszenny bez jajek”, więc pasuje
tylko makaron z jawnym „durum”, „semolina” lub „bez jaj”, a nigdy „jajeczny”. Rabat nie może
podsunąć produktu z alergenem, którego przepis nie deklaruje.

### Działy sklepu

Bot czyta nadal dwa działy ALDI (warzywa, owoce) — tylko te adresy są uzasadnione w kodzie
i w raporcie `apps/web/reports/offers-bot.json`. Nie dopisano innych adresów, bo bez sieci nie
da się potwierdzić, że istnieją i mają strukturę `__NEXT_DATA__`. Do sprawdzenia i dodania
(na stronie sklepu): nabiał (mleko, masło, jaja, sery, jogurty, śmietana, kefir), mięso i
wędliny (pierś z kurczaka, mięso mielone, szynka), ryby (makrela, tuńczyk), pieczywo, produkty
suche (mąka, cukier, ryż, kasze, makaron, płatki, strączki, przyprawy, oleje), mrożonki (owoce
leśne). Po sprawdzeniu adresu można go użyć bez zmiany kodu:
`node apps/web/scripts/offers-bot.mjs https://www.aldi.pl/produkty/<dział>.html`.

## Ranking (CNT-027)

- Liczą się wyłącznie oferty, które przechodzą `isDisplayableAutomaticOffer` (pełny kontrakt
  CNT-016 i aktualność w chwili `now`). Reguły CNT-016 nie zostały osłabione. Notatki
  użytkownika (bez zasięgu, waluty i czasu odczytu) nie wpływają na ranking.
- Produkty spiżarniane `salt`, `water`, `blackpepper`, `oil` nie liczą się do składników.
  Uwaga: `pepper` w katalogu to świeża papryka, więc jest zwykłym składnikiem.
- Kolejność: więcej dopasowanych składników → wyższy udział (dopasowane / liczone) → kolejność
  pierwotna. Przepisy bez dopasowań zostają na końcu w pierwotnej kolejności. Sortowanie jest
  stabilne i nie zależy od kolejności ofert ani od strefy urządzenia.
- Oferty o zasięgu `unverified` (wszystkie z ALDI) są liczone, tak jak w znaczniku „Promocje”
  z CNT-016 — do potwierdzenia przez właściciela.
- Nie zwracamy sumy koszyka (`cheapestTotal`): ceny ofert dotyczą różnych jednostek (kg, sztuka,
  opakowanie) i nie są przeliczane na ilości z przepisu, więc suma byłaby fałszywą ceną.

## API dla interfejsu (CNT-029)

```js
import { promoCoverage, rankByPromotions, ingredientOffers, pantryProducts, safeOfferUrl } from './domain.js';

rankByPromotions(recipes, offers, now?) → Recipe[]           // te same obiekty, nowa tablica
promoCoverage(recipe, offers, now?) → { matched:[{product, offer:OfferView}], count, countable, share }
ingredientOffers(recipe, offers, now?) → [{ product, amount, pantry, offer:OfferView|null }]  // kolejność składników

OfferView = { id, product, name, price, currency, unit, store, from, until, validUntil,
              url /* https albo null */, scope /* kopia */, conditions, regularPrice /* liczba albo null */, fetchedAt }
```

- Najlepsza oferta produktu: najniższa cena nominalna; przy remisie ta ważna dłużej (późniejsze
  `validUntil`), potem mniejsze `id`. Ceny porównywane są wprost, bez przeliczania jednostek.
- `url` przechodzi przez `safeOfferUrl`: tylko `https:`, bez danych logowania, bez znaków
  `"'<>` i spacji, do 500 znaków; inaczej `null` (oferta zostaje, bez linku).
- `name`, `unit`, `conditions`, `scope.note` to tekst ze źródła — widok musi go escapować.
- Cenę formatować `formatCurrency(price, {currency})` z `market.js`; zasięg opisywać jak w CNT-016.
- `evidence` nie trafia do `OfferView`.
